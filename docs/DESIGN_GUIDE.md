# 01 · 选型思路：先想清楚要做哪一只鸭子

做机器人很容易从“先买电机”开始，但我更建议先把整套方案看一遍。电机决定连接件怎么画，电池的位置影响重心，传感器的安装方向又决定程序看到的身体姿态。它们最后都要在同一台机器人上配合。

这一版的目标，是用 S288 和现成电控把 Microduck 的机械、训练与真机运行接起来。尽量使用成品板卡，减少自制 PCB 的工作；线束是否能完全免焊接，还要等最终接头和转接件确认。

## 1. 先认识控制链路

```text
训练电脑：仿真里的鸭子反复练习 → checkpoint → 导出 ONNX
                                                   ↓ 复制到树莓派
真机：IMU + 电机反馈 → 树莓派运行 ONNX → 14 个关节目标 → 电机
```

可以把策略理解成一个根据身体状态不断调整关节目标的程序。它每秒做 50 次决定。树莓派不需要在现场重新学习，运行已经训练好的策略即可。

这也解释了为什么换了电机，不能只改通信代码：仿真里的电机能力、延迟和传动间隙，也要尽量接近实物，否则它学到的动作未必做得出来。

## 2. 为什么用 S288？

原版 Microduck 使用 Dynamixel XL330，这个复刻版本围绕 S288 做适配。这里的选择是整套工程路线，不是单看标称扭矩就判断哪颗电机更好。

| 要考虑的事 | 在这版项目里意味着什么 |
| --- | --- |
| 能不能装进去 | 电机座、输出连接件和支撑结构都要匹配 S288，不能直接沿用 XL330 的承力件 |
| 能不能控制和读数 | 需要匹配的通信板、协议与驱动，目前驱动使用 6 Mbps 串口 |
| 读到的位置代表哪里 | 当前策略使用转子折算到输出侧的位置和协议速度，输出端编码器另作日志诊断 |
| 仿真能不能近似实物 | 使用 S288 的 M1 BAM 执行器配置，并加入传动间隙随机化 |
| 以后能不能复现 | 型号、固件、连接件、标定和策略版本需要一起记录 |

“转子位置”和“输出端位置”为什么要分开？减速机构有间隙，电机内部转了少许，外面的连杆未必立刻跟上。这版让策略与内部控制使用相匹配的转子侧反馈，输出端读数仍然留下来，方便看两者的差异。

完整厂家规格、采购链接和同条件性能对比还没整理齐，所以这里不写“比原版便宜多少”或“性能提高多少”。仿真里的 **0.55 Nm 限幅**也只是当前训练配置，不能当成 S288 的厂家额定扭矩去采购。

## 3. 为什么主控用树莓派？

Pi Zero 2 W 负责四件事：读 IMU、收发电机数据、运行 ONNX、保存日志。现有部署代码已经按这条路线适配，复刻时先沿用它，可以减少同时排查的变量。

这里使用宇树官方 USB 电机通信板，与 UniArm L1 使用的板卡相同，和 S288 电机从同一购买入口购入。前期它连接电脑，完成编号与总线测试；后期再接到 Pi。电机通信板负责把主机的 USB 连接到电机总线。它的协议、速率和针脚都要与 S288 配套，不能看到“USB 转串口”就默认能用。

IMU 使用 LSM6DSV16X。它告诉策略身体怎样旋转、重力朝哪边。除了芯片型号，模块电平和安装朝向也需要确认；装反了轴向，启动时做一次校准并不能纠正。

如果手头已有其他主控，可以研究移植，但要重新检查 ONNX Runtime 是否可安装、串口与 I2C 是否可用，以及完整控制循环能否稳定达到 50 Hz。只测一次网络推理耗时还不够。

## 4. 电源和结构也属于控制方案

实物使用 **3S 航模锂电池**，通过一根 Y 型线分成电机和 Pi 两路。调试记录也使用过稳定 12 V 台架电源；训练中的电压随机化范围仍为 11–12 V，没有随实物供电说明改动。

Y 型线一路接宇树电机通信板，另一路接 **12 V 转 5 V 降压模块**，再给 Pi Zero 2 W 供电。分线只分配电源，降压由模块完成。电池容量、C数、连接器和降压模块具体型号仍需补齐；电机动作时的压降、接头松动和 Pi 供电不稳，都可能影响运行。

结构方面也先保持同一版：整机原鸭头、15 个舵机，其中 14 个关节参与当前 RL。当前模型按电池 155 g、头部 Pi 18 g 记账。它们是模型记录，不是采购规格；更换电池或加摄像头后，还要考虑部件位置、重心和惯量，不能只让总重量相同。

## 5. 第一次复刻，哪些地方先保持一致？

建议先固定电机型号、机械版本、IMU 朝向和配套策略，把一条路线跑通后再逐项修改。尤其不要一边换头部、一边换电池，又顺手调整运行增益；出了问题会很难判断是哪一处变化引起的。

后面会反复遇到三个名字，先记住区别就够了：

- **q=0**：模型定义的关节零位，用来做本机标定。
- **HOME**：训练使用的默认站姿，关节不一定是零角度。
- **ONNX**：树莓派运行的策略文件，要与上面这套硬件和控制定义相配。

读到这里，你应该能说明白：哪台电脑负责训练、谁负责控制电机，以及为什么不能把其他 Microduck 的策略直接放进来。接下来进入[安装教程](BUILD_GUIDE.md)，把方案变成实物。
