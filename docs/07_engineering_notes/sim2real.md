# Sim2Real：如何解释仿真与真机差异

## 1. 为什么零速稳定还不够

站立时主要验证准静态姿态、基本增益、HOME和部分观测接口。起步还包括动作快速变化、支撑切换、惯量、接触和动态执行器响应，因此零速稳定不能证明整套模型完全正确。

## 2. 先核对接口，再调整参数

最先检查同ONNX是否读取相同物理含义的输入：gyro/gravity坐标、rotor q、协议qdot、last_action、command和HOME。观察维度相同并不代表语义一致。

旧M1诊断曾比较`q=OutPos/qdot=rotor`与`q=rotor/qdot=rotor`。历史报告显示后者动作变化明显减弱，但两次完整时长不同，应使用共同窗口分析。该结果支持检查反馈语义，不是当前model9999对全部硬件性能的证明。

## 3. 比较真实command，而不是只对齐运行时间

固定command入口可使用smoothstep，键盘入口则直接改变命令。即使最终vx相同，起步过程也可能完全不同。

比较时记录policy实际收到的command，检查推力、噪声、初始姿态、voltage与lag。不能把被随机外力推倒的play与无同等外力的真机直接比较成同工况结果。

## 4. 从输出和响应判断差异

| 观察 | 值得继续检查 |
| --- | --- |
| target相近，rotor先明显分叉 | 执行器、时序、负载与零位 |
| IMU/重力方向先分叉 | 整机质量惯量、姿态、接触和传感器方向 |
| action先变激进 | 先查之前的观测变化，而非只看最终qdot |
| OutPos跳而rotor平滑 | 输出侧机械/传感映射，不能直接认定backlash |

“谁先分叉”依赖时间戳、初始状态和数据口径，不能只凭曲线看起来相似给出因果结论。

## 5. Real target replay的价值与限制

将真机实际发送的目标按TX时间输入仿真，可减少policy输出差异的影响。但重放需要考虑已有目标处理和command lag，不能将同一发送延迟重复加入。

真实root高度、接触力、被动传动状态和支撑未知时，sim会有不同承载。旧replay报告中既有sim提前姿态分离，也有动态膝速度接近的样本，因此不支持“真机永远比仿真软”的统一结论。

## 6. 参数与模型复杂度

rotor−OutPos差值可能包含偏置、角度相关映射、柔顺和摩擦。差值总摆幅不能直接当作机械齿隙宽度，也不应为了复现振荡人为放大backlash或噪声。

当前公开配置使用一致的rotor反馈和物理被动传动DR。它是明确的训练假设，不是已经完整还原所有输出端动态。

## 7. 结论

数值一致、闭环仿真一致和实机迁移是三个层次。保留真实数据和实验条件，逐层定位，比同时修改观测、执行器、reward和部署补偿更有解释力。
