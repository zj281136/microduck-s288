# PD、BAM与S288执行器建模

## 1. 背景

仿真里将关节目标直接交给近似理想PD，可能低估真实电机的饱和、摩擦和时序影响。S288复刻需要保留电机内部控制规律，同时将已知执行器特性带入训练。

## 2. PD与BAM不是二选一

PD描述控制律；BAM描述如何建模实际执行器。当前M1 adapter包含PD请求、齿比/M1比例映射、电压相关力矩限幅及摩擦。它仍然是目标位置控制，而不是让policy直接输出电机转矩。

```text
q_target
  → firmware PD（rotor q/qdot）
  → gear_ratio² × M1 ratio映射
  → 当前电压下的输出力矩限幅
  → M1摩擦与物理动力学
```

策略的动作尺度、HOME与观测不因使用BAM而另行改变。

## 3. 当前配置的来源

| 参数/结构 | 依据 | 边界 |
| --- | --- | --- |
| Kp/Kd | 所选参考配方固定SDK设置 | 不是传动弹簧刚度/阻尼 |
| M1 ratio、摩擦与armature | 既有S288拟合参数文件 | 不代表整机15颗个体完全一致 |
| 输出限幅0.55Nm@12V | 当前V0 task显式配置 | 不是厂家额定值，也不等于真实固件新增了同样限制 |
| command lag | 既有传输/调度近似 | 不等于完整机械相位滞后 |
| passive参数 | XL330结构参考与训练DR | 不是S288逐关节辨识结果 |

JSON中的`max_torque≈14.91`不能单独解释为真实可用输出力矩；应查看adapter和task中的独立限幅。

## 4. 零位与辨识参考

单轴台架拟合的`q_offset`可能包含摆臂和夹具安装零位。它不是机器人14个RL关节的通用零点，不能替代每台机器的rotor标定。

同样，辨识数据中的单电机command delay不能无条件替代整机总线时序。推理、逐电机发送、包龄和固件内部响应需要分别理解，避免重复叠加相同延迟。

## 5. 比较时应记录什么

在相同增益、目标、供电和负载下，对比target、rotor位置、协议速度、torque及TX/RX时间。若机器人支撑或接触条件变化，就不能仅凭target-error差异认定电机增益错误。

## 6. 当前结论与限制

M1提供了比理想PD更具体的执行器近似，但不能据此宣称动态带宽、温度、负载、供电和传动均已完整辨识。零速站稳、单轴跟随和整机行走分别验证不同部分，不能相互替代。
