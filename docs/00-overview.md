# 先认识这只鸭子

Microduck-S288 整机使用 15 个舵机，其中两条腿各 5 个、颈部和头部 4 个，共 14 个关节参与当前 RL；第 15 个不进入当前策略。树莓派读取电机与 IMU，运行策略，再把目标位置发回电机。这个过程不断重复，鸭子才能一边感知身体，一边调整动作。

下面先把几个名字解释清楚。后面看到 q、HOME、BAM 或 ONNX 时，就能知道它们在这只鸭子里负责什么。

## 它怎么决定下一步动作？

每个策略周期，Pi 把关节状态、角速度、重力方向和速度指令整理成一份输入。神经网络读完后，输出 14 个动作值，再结合默认站姿 HOME 得到各关节目标。

```text
关节反馈 + IMU + 指令
        ↓
     61D 观测
        ↓
   policy 神经网络
        ↓
     14D 动作
        ↓
 HOME + action → 电机目标
        ↓
 电机和机构运动 → 下一次反馈
```

配置里的策略频率是 50 Hz，也就是约每 20 ms 做一次这样的判断。电机内部还有自己的 PD 控制环，负责跟踪收到的目标。

## 同一个电机，为什么有两种位置？

S288 的回包里既有转子位置，也有输出端的 OutPos。两者隔着传动机构，所以不一定完全重合。

| 名字 | 可以怎样理解 | 这版怎么用 |
| --- | --- | --- |
| rotor | 电机内部转子位置，按齿比折算成关节角度 | 给 policy 和内部 PD 使用 |
| OutPos | 输出轴那一端的绝对位置读数 | 留在日志里观察传动差异 |
| physical joint | 仿真里真正带动连杆运动的关节状态 | 影响支撑、接触和身体姿态 |

这版选择让 policy 的位置、速度与电机 PD 使用同一侧的状态：**rotor q + rotor qdot**。OutPos 仍然记录，方便研究输出端和转子端相差多少。

为什么这样选、之前遇到了什么，放在[Sim2Real 笔记](07_engineering_notes/sim2real.md)里讲。

## HOME 是站姿，不是标定零位

HOME 是训练时的默认站姿。policy 看到的位置是 `q−HOME`，目标也是从 HOME 叠加 action 得到。

标定用的则是模型 `q=0` 姿态。把这两件事分开，后面就不容易出现“明明站得挺直，一进 RL 却开始偏”的疑惑。

## 仿真里还多了什么？

真实传动不会完全刚性地跟着电机转。为了让训练考虑机械间隙，每个主动 rotor 关节后还安排了一个没有独立电机的被动 hinge。

```text
S288 M1 BAM → 主动 rotor 关节 → 被动传动间隙 → 连杆
```

policy 仍只看主动 rotor 状态。被动关节通过物理运动影响连杆、接触和 IMU。当前总 play 随机范围为 2–4°，是训练覆盖范围，不代表已经测出所有电机都有同样的间隙。

详细公式和参数集中在[控制接口](05-control-contract.md)，刚开始制作可以先知道这层关系。

## 电脑和树莓派怎么分工？

| 设备 | 负责的事 |
| --- | --- |
| 训练电脑 | MuJoCo/Warp 仿真、PPO、保存 PT、导出 ONNX |
| 树莓派 | ONNX 推理、IMU、电机通信、日志和退出处理 |

只想使用预训练策略，可以先不安装训练环境。想自己改步态，再进入[训练教程](06-training.md)。

V0 模型记录了 155g 电池和 18g 头部 Pi，编译模型总质量约 733.3g。它是软件质量之和，不代替装完线束、紧固件后的实际称重。

## 这套资料对应哪个版本？

```text
Mjlab-Velocity-Flat-S288-v0-BacklashDR-RotorOnly61D-MicroDuck
```

名字比较长，可以先记成“原鸭头、S288、rotor-only、BacklashDR”。仓库的 `model_9999` ONNX 与它配套。用同一套版本阅读模型、标定和部署，排查时会省不少麻烦。

## 后面会碰到的几个词

| 名字 | 意思 |
| --- | --- |
| policy | 读状态、输出动作的策略网络 |
| actor / critic | 输出动作的网络 / 训练时估计价值的网络 |
| episode / reset | 一段仿真经历 / 开始下一段经历 |
| rollout | 策略与环境交互形成的一段轨迹 |
| DR | 训练时改变一些参数，让策略接触更多可能情况 |
| BAM | 用于描述真实执行器特性的模型方法 |
| contract | 模型与运行代码约定好的输入、输出和坐标含义 |

不需要一次记完，实际用到时再回来查就好。
