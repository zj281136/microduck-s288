# 单关节、IMU 与通信测试说明

本章介绍现有工具能检查什么，以及哪些测试仍需补充记录。所有硬件命令由操作者人工执行；未观察到结果的步骤保持未验收。

## 1. 测试前准备

- 机器人由可靠支架承重，零增益时不会掉落。
- 确认动力切断位置和电气极性。
- 标定、部署和诊断进程不能同时占用串口。
- 先确认电机 ID，再捕获模型 q=0 零位，最后验证 direction。

## 2. 原始反馈检查

现有 `teleop/scripts/probe_s288_bus.py` 可以发零增益请求并读取原始字段：

```bash
.venv/bin/python teleop/scripts/probe_s288_bus.py \
  --port /dev/ttyACM0 --ids 0 1 2 3 --samples 3
```

命令在 `software/deployment` 执行。它会打开串口、发送协议帧，不是完全不访问硬件的文件检查。

先检查小组，再检查全部电机。关注回包 ID、错误码、有限数值、请求时延和电压；出现超时、CRC 或 ID 错误时应先排查通信。

## 3. 单关节小角度方向测试

复用现有 rotor 标定工具，先捕获该关节参考，再指定 `--motor-id` 执行方向测试。例如 ID3 对应 neck_pitch：

```bash
.venv/bin/python teleop/scripts/calibrate_microduck_s288_rotor.py \
  --port /dev/ttyACM0 --motor-id 3 --calibrate-directions
```

该命令需要已有零位文件，并会驱动选中的电机。默认小角度测试参数来自既有脚本：偏移0.10rad、过渡1.5s、较低测试增益；不等同于 RL 运行增益。

已有有效 direction 的条目会保留并跳过，不会因为重新执行命令就自动重测。运动与 MuJoCo 正方向不符、结构干涉、通信错误或速度异常时应停止，不能继续用其他关节补偿。

## 4. IMU 检查

现有驱动在 `teleop/robot_control/imu/lsm6dsv16x.py`，采用机器人 X前、Y左、Z上约定。需要检查：

| 检查 | 应记录内容 |
| --- | --- |
| 静止 | gyro偏置、噪声、温度、gravity方向 |
| 方向 | 人工缓慢改变roll/pitch/yaw时对应轴和符号 |
| 时序 | 实际采样率、数据年龄、陈旧帧情况 |
| 安装 | 传感器板朝向、固定方式、供电与接口 |

独立 IMU 检查命令已补入[软件安装教程第 5 节](../03_software_setup/environment_setup.md#5-安装-imu并通过-i2c-与树莓派通信)：先扫描地址、读取 WHO_AM_I，再用当前驱动连续观察 gyro、accel 和 gravity。它不控制电机；实物测试记录仍需操作者保存。

## 5. 通信质量

probe提供样本；完整验收还需记录请求数、有效包、超时/CRC/ID错误、每电机延迟、反馈年龄、实际控制频率和电压。长期测试的已验证命令与统计图：`TODO`。

串联线束长度、接插件、供电与控制器均可能影响通信。测试中一次只改变一个因素；缺少修复前后统计时，不将某个单独因素写成已证实根因。

## 6. 进入整机测试的条件

ID、零位、direction、IMU方向和通信均经实际检查后，进入受保护零速站立。完整顺序见[硬件验收表](hardware_validation.md)，运行步骤见[真机部署](../07-deployment.md)。

测试记录应包含模型SHA256、启动参数、供电和支撑条件。软件停止会尝试撤去增益；总线失效时仍需独立切断动力，且支架应能承重。
