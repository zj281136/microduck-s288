# 打印之前，先把模型文件分清楚

仓库里有XML，也有STL，但它们不全是拿去打印的零件。先花一点时间认清文件用途，能避免打印尺寸不对、左右件混用，或者装到一半才发现孔位不匹配。

## 1. 这些文件分别拿来做什么？

| 类型 | 本项目中的作用 | 能否直接用于打印 |
| --- | --- | --- |
| MJCF / XML | 关节树、惯量、碰撞、限位和传感器定义 | 否 |
| 仿真 STL | 可视化与模型几何资源 | 需核验，不能默认可打印 |
| 可编辑 CAD | 连接面、孔位、公差和结构修改 | 需导出打印文件 |
| 已验证打印 STL | 实物装配使用的几何 | 按对应版本和打印说明使用 |

训练资源位于 `software/training/src/mjlab_microduck/robot/microduck/`。`robot_walk_s288_v1.xml` 是 V0 构造链使用的基础模型，Python 配置会继续应用电池、Pi 质量及被动关节设置；仅在查看器中打开基础 XML，不一定等于最终训练模型。

## 2. 单位与坐标

仿真长度采用米。STL 本身通常不携带可靠单位，导入后应以电机外形、已知孔距或实物长度校验尺寸。若源文件以毫米导出，换算到米的缩放为 `0.001`。

组装相关零件应保留共同装配坐标。分别执行“居中到原点”会丢失相对位置；将这些 STL 原样挂到同一 link 时，装配关系就会错误。

至少核对：尺寸、左右件、安装面、输出轴位置、孔距、轴心和连杆方向。几何中心不等于转轴中心，也不等于质量中心。

## 3. 打印前准备

S288 与 XL330 的外形和输出连接方式不同，承力连接件需要使用匹配的 S288 设计。模型资源的外观相似不能证明舵盘、螺钉和轴承可直接通用。

| 参数 | 当前资料 |
| --- | --- |
| 材料与牌号 | 待完善 |
| 喷嘴、层高、线宽 | 待完善 |
| 壁数与填充 | 待完善 |
| 各零件朝向及支撑 | 待完善 |
| 嵌件、螺孔和轴承配合 | 待完善 |
| 已打印验证的文件版本 | 待完善 |

打印件应记录文件版本和打印参数。对于电机座、舵盘、轴承孔等关键配合，先完成局部试装，再批量打印整套零件。

## 4. 打印后核验

清除支撑后，检查承力层、孔口和连接面；试装电机、轴承和紧固件。转动连接处应能按设计活动，固定连接处不应依靠强行挤压维持位置。

装配后记录每个部件的实际质量。重量应注明是否包含螺丝、轴承、线缆和嵌件，避免在整机模型中重复计入。

## 5. 修改模型时的同步关系

几何、质量和惯量是不同配置项。带显式惯量的 MJCF 不会因为替换可视化 STL 就自动得到正确的新动力学。

结构变更后需依次核对：安装变换、部件质量、重心、惯量、碰撞几何及关节限位。更重的头部还会改变颈部力臂和整机重心，不能只调整总质量。
