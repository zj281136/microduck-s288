# 三种部署路线

| 路线 | 输入 | 需要GPU | 使用入口 | 验证前提 |
| --- | --- | --- | --- | --- |
| 预训练快速部署 | 仓库ONNX+manifest、本机标定 | 否 | deploy.py check → probe/calibrate → stand | 型号/接线/零位/IMU/支撑逐项核对 |
| 自训练模型 | 匹配task PT → 官方导出ONNX+更新manifest | 训练阶段需要 | inspect/数值/闭环验证 → 相同部署入口 | 导出新入口和ONNX闭环流程仍有待验证项 |
| 诊断 | 串口、选定ID、正确支撑 | 否 | probe/现有交互方向测试 | probe会发送零增益命令；方向测试会运动 |

详细命令保留在[Pi部署教程](../07-deployment.md)。统一入口无参数默认为check；原运动入口要求`--arm-ground-test`，不增加开机自启动服务。

## 首次受保护站立

1. 确认[硬件验收](../04_calibration/hardware_validation.md)各项实际通过，不用文件检查代替。
2. 双脚着地，防坠保持松弛但能承重；电源急停可触及。
3. IMU校准时静止，固定command显式写`--vx 0 --vy 0 --wz 0`。
4. 短时STAND/RL，保存CSV和abort。异常时停止，不提高max-speed。

## 首次低速

只在站立验收后人工修改固定vx，例如0.05m/s，保留3s smoothstep与短duration。它是待实机验收的示例，不保证该策略在此速度一定走。键盘的0.20m/s固定档位不是首次低速验证入口。

## 停止

Ctrl+C/安全故障后软件尝试下发零增益/零转矩并关闭串口；总线故障时不保证命令送达，必须有独立动力切断。零增益时机器人不能主动站稳，防坠需承重。不要将软件检查描述为自动保证安全。
