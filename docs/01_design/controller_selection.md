# 主控、通信板和IMU选型

## 1. 为什么保留树莓派

现有部署链路在Pi上完成ONNX推理、串口请求、IMU采集、日志和安全退出。Pi Zero2W与当前安装方式、依赖和运行入口配套，因此公开方案继续保留这一平台。

训练电脑负责GPU仿真和PPO，Pi只执行导出后的策略；选择Pi不意味着可以在Pi上运行同规模训练。

## 2. 选型指标

| 部件 | 关注指标 | 当前方案 | 待确认 |
| --- | --- | --- | --- |
| 主控 | 架构/ORT兼容、USB/I2C、供电、固定与质量 | Pi Zero2W | 系统镜像、长时负载和散热记录 |
| 通信板 | S288协议兼容、波特率、接口、时序和线束 | 宇树官方 USB 电机通信板，UniArm L1 同款，与 S288 同一购买入口购入 | 固件版本与针脚 |
| IMU | gyro/姿态信息、数据时效、安装方向与接口 | LSM6DSV16X | 模块版本、电平和安装图 |

## 3. 为什么使用成品通信板

控制器负责Pi与电机总线之间的硬件连接，现有代码通过串口访问它。复用成品板卡有利于降低自制PCB和焊接门槛，但成品线束能否直接购买、是否需要转接仍取决于实际连接器。

通信并不只是“波特率设置正确”：15颗电机在全总线测试时串行收发、线束、供电和日志调度都会影响每帧反馈年龄与循环时间。

## 4. 性能描述的边界

原鸭头model9999历史记录中Pi推理P95约0.775ms。该结果对应特定模型和系统，只描述推理耗时，不等于完整50Hz循环或任意Pi设备都满足实时要求。

更换主控后应重新核对ORT、串口/I2C、时间戳、循环频率和供电。仅复制Python脚本不能证明硬件时序一致。

## 5. IMU固定与坐标

IMU板必须固定可靠，并与驱动中的传感器到机器人坐标转换匹配。偏置校准不解决安装轴方向错误，见[电气连接](../03-electronics.md)及[IMU测试](../04_calibration/testing.md)。
